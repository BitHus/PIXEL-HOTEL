Drag-pan (follow ON), release, 2.5 s later the shown camera moves 187 screen px in ONE frame (t +2567 ms) back to the avatar: every guest, the avatar and the room "teleport" at once. Cause: client/src/game/gameLoop.ts (ticker, the `prefs.followCamera ... followLock(...)` block) calls shared/src/cameraFollow.ts followLock, an instant lock with no glide, as soon as followPaused() (client/src/game/followCam.ts, CAMERA_FOLLOW_PAUSE_MS 2500) turns false. Needs an eased return (followStep with tau, or ease over ~300 ms) when the pause ends; the lock may stay once centred. Spec: 'follow ON: free pan then return to the avatar is smooth' (fails, worst 187 px/frame, limit 40).
2. (HIGH) The AVATAR snaps after a pan cancelled its walk. A tap on the floor starts a walk (api.walk, API walkState), a quick drag then pans and pointerInput.ts onWalkCancel calls g.stop() (avatarWalk.ts stop): the client avatar halts at once but the API's walkState keeps walking to the old goal. Measured 2.5 s later: client avatar (131,196), api.avatarNow() (151,179), gap 26 px; the next tap sends api.walk from the API position and avatarWalk.ts follow() snaps the client avatar when the gap is over WALK_RESYNC_PX (24). In the first sampler run the avatar snapped 28, 91, 66, 58 px in one frame (96 px per 17 ms frame, limit 5.4) at each tap after a pan, follow ON and OFF. Cause: stop() never tells the API. Fix idea: after stop() call an api.walk to the avatar's own position (or add an api.stopWalk), so API and client agree. Spec: 'pan that cancels a walk leaves client avatar and API avatar in sync' (fails, gap 26).

(LOW) Slow frames (CPU x6 throttle, frames up to 483 ms, as on a weak phone while panning): shown guest vs model gap reaches 24 to 38 px for 93 frames and one guest snapped 38 px in one frame (333 ms frame, limit 33).
