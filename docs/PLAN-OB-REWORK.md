# PLAN-OB-REWORK: mine (OB-6), fishing (OB-7), ground drops and rarity (OB-8)
Written 21 Nov 2026. Docs only. Owner notes are in docs/ROADMAP.md OB-6, OB-7, OB-8. Brief sections 10, 10c, 10d stay valid unless a line below says "BRIEF CHANGE" (the manager updates CLAUDE.md and docs/BRIEF.md when a job lands). Numbers marked OWNER OPEN are proposals, not decisions. All ideas are original; other games are only used as a feel reference.

## 0. Research (standard web search; thin results, so the rest is design judgement)
- Hit feedback: layered effects each answer one question: flash = it landed, particles + sound = where, camera shake = how hard, hit stop = a special moment. Shake should scale with a trauma value squared (small hits barely move). Overused shake tires players, so for a REPEATED action (hold-mining) use almost none and put the weight on particles, sound and a squash of the block. Particles should fly away from the hit direction.
- Fishing (Stardew wiki): the bite wait is random (0.6 to 30 s, bait and skill shorten it, never under 0.5 s), the bobber wiggles + "!" + sound, then the player starts the minigame. The wait is the suspense, the signal is clear and audible, the window is short but fair.
- Rarity (Core Keeper, Terraria wiki): rarity is shown by the COLOUR OF THE NAME across all items; Risk of Rain adds a coloured border and drops that despawn after 30 s on the ground.
- No usable results for hold-mining rhythm, exit/portal search, drop magnets. Those parts below follow common practice (Terraria-style magnet radius, Forager-style pop-out arcs, Stardew-style "!" cue) and need the owner's eye in play, not a source.

## 2. OB-8 first (it is a dependency of OB-6 and OB-7): ground drops and rarity everywhere
### Design
- A DROP is a small world entity: `{ id, item, qty, rank, x, y, vx, vy, ageMs, state: 'pop'|'rest'|'magnet' }`. When a thing breaks or a chest opens, drops pop out on a short arc (60 to 160 ms flight, small bounce), lie still (gentle bob, a coloured glow ring by rank), and fly to the avatar when it is within MAGNET_PX (OWNER OPEN: 48 px; gems and gold 80 px) after a PICKUP_DELAY_MS (OWNER OPEN: 350 ms so the pop is seen). On contact (under 12 px) the item enters the bag through the ledger (same reasons as today: nothing changes in the economy). Gems flying to the character stay (the owner likes it): gems have a faster, curved magnet.
- Bag full: the drop stays, a toast "Bag full" once, the drop gets a small "!" and keeps waiting; in the dungeon and mine nothing despawns during the run. Hotel, tavern, farm: drops (from harvest or punching) use the same system with a short magnet (full reach) so nothing is left behind; they never despawn but are saved as bag items if the room is left (leave room = auto collect, because loose state in saves is a risk).
- Despawn: dungeon and mine drops live for the whole run; OWNER OPEN whether they time out (proposal: no timeout, the run ends = bag settles, uncollected drops of a CLEARED room are auto-collected at the exit stairs with a "swept up" popup, so nothing is lost by a missed pixel).
- Death: drops on the floor are lost with the bag (same rule as the bag).
### Rarity shown everywhere (RARITY-UI)
One shared look, from RANK_COLORS: name colour, slot border, a drop glow ring + beam, sparkle for ultra rare and legendary (existing `sparkles`), and a one-line rarity word. Surfaces: drop on ground, pickup popup, bag and hotbar slots, chest opening, mine block name when glinting, fish catch popup, Book, catalog, orders strip, quest rewards, level-up toast. "Numbers and events can be rare too": a RARE EVENT (see 3.5) and a record catch carry the same rank colour and word; a `rank` field is added to events and popups, not to money. Ranked gold amounts: a gold pile gets a rank by size relative to the depth (OWNER OPEN, only a colour, never changes value).
### Files and pure functions
- NEW shared/src/drops.ts: `Drop`, `spawnDrops(source, items, rng, cfg)`, `stepDrops(drops, avatar, dtMs, bagFree)` returning `{drops, picked: Drop[]}`, `scatterArc(rng, i, n)`, `magnetStep(drop, avatar, dtMs)`. Pure, rng and time passed in, fixed 100 ms ticks inside the dungeon step.
- shared/src/dungeon/run.ts (Run gets `drops: Drop[]`), step.ts / mineStep.ts (breaking and chest opening call spawnDrops instead of addToBag; the step calls stepDrops each tick and addToBag on `picked`), runBag.ts unchanged.
- NEW shared/src/rarityView.ts: `rarityLabel(rank)`, `rarityStyle(rank)` (colour token, glow level, beam yes/no); config.ts: DROP_* constants (MAGNET_PX, PICKUP_DELAY_MS, POP_MS, DROP_CAP_PER_ROOM).
- client: client/src/render/dropView.ts (sprite from drawIcon, glow, shadow, bob), client/src/dungeon/dungeonFx.ts (pickup fly, sparkles), ui: one `rarityChip` helper used by slots and popups (client/src/ui/rarity.ts).
### Data shapes and SAVE
- Drops live inside the run (`Run.drops`), not in GameState: no save change if runs are not saved mid-run. CHECK: if a run is persisted (it is part of LocalGameAPI state), a missing `drops` must read as `[]` (optional field, no migration). Only if the owner wants drops in the hotel/tavern persisted does SAVE_VERSION bump (44, with `Room.drops`); this plan does NOT do that (auto-collect on leave).
### Tests
drops.test.ts: arc is deterministic for a seed; magnet only inside radius and after delay; pickup adds exactly once through the ledger; bag full keeps the drop; sweep at the exit collects all; death loses them; no duplicate pickups under a tick of 100 ms with a fast avatar. step.test.ts / mineStep.test.ts: same items and gold as before for a seeded run (parity: the totals do not change, only the route into the bag). rarityView.test.ts: every rank has a label and colour.

## 3. OB-6 mine rework
### 3.1 Smooth punching (and hold-mining)
Cause to verify first (job M1): a block breaks only after N whole hits at 400 ms with no in-between feedback, and hold-repeat restarts per cell. Design:
- Per-block HIT PROGRESS (`dig.progress[cell] = hitsDone`) already exists via hits; add visual stages: crack overlay 0 / 1 / 2 by hits/total, a 2 px squash-and-recover of the block on each hit (80 ms), 3 to 5 chip particles flying away from the avatar, a tick sound with pitch rising per hit, and a small crumb pop on break. A cooldown bar is not needed.
- Hold rhythm: cooldown 400 ms stays (OWNER OPEN: 320 ms), but the next hit is queued so holding gives an even beat, and sliding to the next block keeps the beat (no restart). The swing animation plays at the cooldown period; the hit lands at the swing's middle frame (not at the start) so sound, particle and crack are in sync.
- Screen shake: none on normal hits; 1 to 2 px for 90 ms on a break of ore, 3 px for 150 ms on a rare gem, a cave-in (trauma squared, capped). Setting "Reduce shake" in Settings (default off; on for reduced motion). Hit stop 40 ms only on rare gem break.
- Files: shared/src/dungeon/mineStep.ts (expose `digHitProgress`, keep the rule pure), client/src/dungeon/dungeonFx.ts (chips, shake via a trauma helper in NEW client/src/dungeon/shake.ts), digArt.ts (crack stages and squash). Tests: progress per cell, hold cadence regression (the interval between hits is the cooldown, never shorter, never a missed beat when moving to a neighbour).
### 3.2 Caves
Generation moves from block noise to named CAVES in shared/src/dungeon/mineGen.ts: a cellular-automata pass (4-5 rule, 2 smoothing steps, seeded) for organic chambers, joined by tunnels, with chamber types from NEW shared/data/mineCaves.json: `{ id, minDepth, size:[min,max], blockMix, mobs, light, specials }` (examples, original: Echo Hall (big and empty, glints), Mushroom Grotto (glowing, slimes), Collapsed Gallery (cave-in tiles, coal), Crystal Vault (gems, laser trap), Flooded Pocket (dead end with a chest)). Invariants (tests): all caves reach the spawn by a walk path after digging at most K blocks (cheapestRoute already exists), exit always exists (see 3.4), same seed = same map.
### 3.3 Mobs and lasers
- Mobs: keep slime and bat; add two original ones as data in the mine mob table (config ENEMIES style, shared/data/mineMobs.json): CAVE MOLE (burrows between cells, surfaces next to you after a hint of cracked floor, 6 hp, slow) and ROCK CRAB (armoured: only the back is weak, hit from behind or after it flips, drops a rare). OWNER OPEN: hp, damage, depth ranges.
- LASER SHOOTERS: static ancient emitters embedded in a wall block (kind `emitter`, unbreakable until its 3-hit panel is exposed). A laser is a straight beam along a row or column with a TELEGRAPH (a thin dim line 700 ms, then a bright beam 300 ms, then a 1500 ms rest); pure function `laserCells(emitter, tickMs)` returns the lit cells; hit = damage on the cells (1 pass per beam, damage OWNER OPEN: 5, scaled by armour). Digging the emitter off disables it and drops a rare "lens" item (craft input, OWNER OPEN). Blocks stop the beam, so the player can hide or tunnel.
- Files: shared/src/dungeon/mineStep.ts (digHazardTick gets lasers and mobs), NEW shared/src/dungeon/mineHazards.ts (laserCells, laserDamage, mole/crab step), mineGen.ts (placement rules: never on the main route cell, never an unavoidable beam on the only path), data files above. Tests: telegraph before damage always (no instant hit), beam blocked by a block, deterministic by tick, never unavoidable path (generator test over 200 seeds).
### 3.4 Hologram portal exit found without dying
Replaces "find the exit as a cement block" (the exit currently can feel missing). Design:
- Every depth has ONE EXIT PORTAL: a hologram arch (blue-white, flickering) placed in a cave far from the spawn by path distance (>= 60% of the deepest cave path). Its position comes from the seed; it is an ordinary entity, not a block, so it can never be buried.
- Finding it is the game, and never needs death: (a) a PORTAL HUM: audio volume and a faint edge arrow on the HUD pulse stronger when closer than 20 blocks (only within the hint radius, so exploration stays); (b) a free item "Beacon shard" each visit? NO (no extra items); instead a skill-tree node "Portal sense" extends the hint radius (existing Ore sense family, live in skills.json, OWNER OPEN); (c) a GUARANTEED path: after PORTAL_PITY_MS (OWNER OPEN: 6 min) in a depth the hum radius covers the whole map and the arrow always shows (pity, never a stuck player). Also a "Leave now" button at any time still banks the ore at half (OWNER OPEN: keep the current half rule on death only; Leave from anywhere without death is the new safe route, the owner asked "without dying"): proposal is a 3 s channel "Rope up" action anywhere, interrupted by damage, banks everything (no loss) but ends the visit. So the exit is never required to leave.
- Files: mineGen.ts (`placePortal(rng, caves, spawn)`; the generated map has `exit: {x,y}` as before so run code stays), mineStep.ts (`portalHint(avatar, exit, elapsedMs)` pure returning `{near: 0..1, showArrow}`; `ropeUp` input), client: client/src/dungeon/portalView.ts (hologram art, scanlines), HUD arrow in dungeonScreen.ts. Tests: exit always reachable in a seeded sweep; farthest-cave rule; hint monotone with distance; pity widens after the timer; rope-up interrupted by damage and not by hum.
### 3.5 Random events
A small seeded event table per visit (shared/data/mineEvents.json, one event per depth at most, roll in generateDigMine): `{ id, rank, minDepth, weight, kind }` with original examples: Glitter Vein (a vein of rare ore with a glint trail), Wandering Merchant Echo? NO (trader is gone: not allowed), Collapse Warning (rumble, then cave-ins for 30 s, reward: a geode), Lost Pickaxe (a free steel-pickaxe use for the visit), Gem Geode Rain (a room where geodes fall as drops, see OB-8), Silent Depth (no mobs, dim light). Events have a rank (OB-8 rarity applies, shown as a banner in the rank colour). Rank weights OWNER OPEN (use RANK_WEIGHTS with a 0.5 multiplier). Pure: `rollMineEvent(seed, depth, rng)`. Tests: determinism, weights sum, no event blocks the exit.
### 3.6 Rare gems topaz and ruby that splice into gem blocks
- Items: `topaz`, `ruby` (and later `sapphire`, `emerald` OWNER OPEN) in shared/data/materials.json and mineBlocks.json as ore-like blocks `topaz_ore`, `ruby_ore` (ranks: topaz ultra_rare, ruby legendary; OWNER OPEN: ranks, hits 5/7, min depth 4/7, weightPerDepth tiny). They drop as OB-8 ground drops with beam.
- Gem BLOCKS: `topaz_block`, `ruby_block` in shared/data/blocks.json (decor blocks; BLOCK seeds `topaz_block_seed` follow the standing rule "every block has a seed item"). Splice: add SPECIAL recipes in shared/data/splice.json: `topaz + <iron seed or any ore-category seed>` = `topaz_block_seed`, `ruby + topaz`? Rule: a gem SPLICES with a basic block seed (stone_seed, OWNER OPEN) to give its gem block seed; gems are not seeds today, so job S1 first checks how splice takes items: if only seeds are splice inputs, add a new item `gem_seed` flow: PLAIN RULE (proposal): "Polish" at the existing splicing step, a gem in the hand + a plant on a block = the gem block seed (a variation of splicing, uses spliceRule + special recipes data). Keep "2 in, 1 out".
- Tests: gems are in the Book, ranks right, splice special recipe present and returns the gem block seed, `balance.test.ts` closed loops: gold per gem through catalog blocks and the seed ratio must not reopen (run `npm run simulate`; the manager checks BALANCE_TARGETS). SAVE impact: new item and block ids only = no migration (ids are data), BUT if any save holds a block list of known kinds check `Book` ids (undiscovered = "???", fine).

## 4. OB-7 fishing
### Design
- BOBBER DIP as the bite: phases stay (wait -> bite -> reel). Change the look and the window: during `wait` the bobber floats and nibbles (existing 2 to 3 nibbles); at the bite the bobber goes UNDER water (a drawn ripple ring + the bobber hidden under a water tint), stays under for the rank's window (existing FISH_BITE_MS; OWNER OPEN: common 900 ms, rare 700, ultra rare 550, legendary 450), then comes back UP: tap while it is under = hooked; tap before the dip ("early") = line pulled up, nothing lost, the cast is wasted with a short "Too early" text (replaces spam-tapping: early taps are penalised by a 0.8 s recast lock; there is NO reward for tapping fast). Tap after it came up = "It got away" (outcome 'missed', as today).
- A calm cue for the dip: a sound (low plop), a 1-frame screen-edge flash is NOT used (shake would tire), a "!" over the water only at the dip (as now). Colour-blind: ring + sound + haptic buzz on phone (navigator.vibrate guarded).
- Then the existing reel minigame, unchanged.
- Catch popup: the item floats above the head (bigger, 2x the old size), shows NAME in rank colour, WEIGHT and a rarity word. Weight: add `kg` derived from cm (`weightKg = round(k * (cm/100)^3 * density, 2)`, per-fish `density` data, OWNER OPEN) so the same cm always gives the same kg (pure `fishWeightKg(type, cm)`). Records: Player.biggest already holds size; weight is derived, so no new stored field. A record catch shows "New record" in the rank colour.
- PIER AND BOAT SIZE: lakeside room data: pier 5 cells -> 8 cells, a bigger boat (3 x 2 cells art, OWNER OPEN: 4 x 2) with 2 cast spots; cast spots are cells (shared/data or lakeside config: `LAKE_PIER_CELLS`, `LAKE_BOAT`). More water cells ("water better": a deeper shade ring near the middle, ripples, reflections in client art only).
- AVATAR NOT ON WATER: the nav grid treats a cell as free only when ALL of it is floor and not water; the bug is the SPRITE standing at the cast point, so: cast spots are shifted back from the shore line so the avatar FEET (the anchor, bottom centre) are on land or planks and the body draws over the water only visually by max 8 px; add a test that every cast spot's anchor cell is walkable and the 32 x 32 cell under the feet has no water cell (`castSpotsValid(lake)`). The beach fix is data plus this validity function, not art squashing (ART RULE).
### Files and pure functions
- shared/src/fishing.ts: phase 'bite' gains `dipMs` (same as biteMs) and `early` outcome handling in `step` (tap in 'wait' = outcome 'early', session goes done); `FishOutcome` gets 'early'. NEW `fishWeightKg`, `fishDisplay(session)` returning `{ name, rank, cm, kg }` for the popup. Config lakeside.ts: FISH_EARLY_LOCK_MS, per-rank bite windows (FISH_BITE_MS exists). Data: fish.json `density` per fish (optional, default 1).
- shared/src/lakeside layout (config/lakeside.ts + LAKE_LEVELS): pier, boat, cast spots; `castSpots(lake)` pure.
- client: client/src/lakeside/pondView.ts (bobber under water, ripple), lakeFx.ts (dip plop, rings), lakeFeel.ts (haptic), lakesideArt.ts (pier and boat art: PixelLab generation at the correct size per the ART RULE, owner cap permitting), a catch popup in ui (rank chip from OB-8).
### SAVE impact
No migration: no new stored field (kg is derived; `early` is a session outcome). If the owner wants a weight RECORD per fish type stored (Player.biggest holds cm only), that is optional and would need SAVE 44 (optional field, migration identity). Default: derive only.
### Tests
fishing.test.ts: early tap = 'early' and no catch, no ledger change; tap inside the dip = reel; tap after = 'missed'; window per rank from config; weight is deterministic and monotone in cm; castSpotsValid over every lake level and the pier; golden determinism of a seeded session (existing fishingSim stays green).
